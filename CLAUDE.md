## The five things that will bite you

0. **Never edit the engine block by hand.** Everything between
   `<!-- three.js engine: begin -->` and `<!-- three.js engine: end -->` is
   generated by `node tools/build-three.js`. Since r111 it is stock three.js
   with physically based lighting, and every light in the game is tuned for
   that: create point lights with `lampLight()`, and multiply anything written
   to a lamp's `.intensity` by `light.userData.lampScale` (PROJECT.md §2,
   "Lighting").

1. **The game is one HTML file.** `app/renderer/index.html`, ~1.42 MB, Three.js
   inlined, no build step. The gameplay block is one IIFE under `'use strict'`.
   A call to a function you deleted is a **runtime** error — the file parses
   fine and the feature is silently dead. This has happened three times.

2. **There is no git.** `revisions/` *is* the history. Never delete an archived
   revision; never overwrite one that has shipped. The live `index.html` and its
   archived copy must stay byte-identical.

3. **Never use a shell heredoc for a script containing a regex, a backslash, or
   a template literal.** The shell eats the escapes. Write the script to a file,
   then run it. Make every edit an exact-match substitution that fails loudly
   when it does not match exactly once.

4. **Emberwatch sends the Dr. Dabber `b9` and `b1`. Nothing else, ever.**
   `b8` is a four-byte factory reset one nibble away from `b9`. `b3`/`b5`/`b7`/
   `ba`/`bb`/`d1`–`d4` all write into stored device state.

5. **Parsing is not evidence.** Verify at runtime with `tools/harness` (see
   PROJECT.md §3). It takes screenshots, so look at visual changes instead of
   assuming them. Never write a number into a doc that was not read off a run.

## Before and after any change

```bash
node tools/check-parse.js     # every <script> block parses
node tools/audit-source.js    # section B and C must stay at zero
node tools/audit-dom.js       # markup ids vs script lookups
node tools/audit-dead.js      # functions nothing live reaches; must be 0
node tools/audit-comments.js  # comments that swallowed a call; must be none
node tools/test-switch-frames.js
node tools/test-switch-b9.js
node tools/test-bluetooth-pairing.js # desktop pairing, no device writes
```

## When you ship

Stamp → archive → variants (build 6/6, then `node tools/check-variants.js`
6/6) → smoke → dist → docs → release notes (`node releases/build-notes.js`,
then push the branch and fast-forward `main` to it; a workflow publishes the
tag and the GitHub release). Every revision is its own release. Full detail in
PROJECT.md §3. **Update PROJECT.md as part of shipping** — it is meant to read
as living patch notes, not a snapshot.
